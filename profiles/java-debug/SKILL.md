# Java defect analysis · version 2

Inspect relevant historical source and request runtime/debugger capabilities for an explicit hypothesis. The registered runtime supplies its target JDK; do not substitute modern libraries for historical dependencies. Use JDK debugging tools only if the readiness observation confirms they exist.

Read source with `read_code`; use `source_search` to locate exact text. Select returned evidence IDs for finding locations and supporting quotes; the provider resolves their coordinates. After a runtime grant, inspect readiness: a generic workspace has no product build or reproducer, so compile unchanged `/input/source` into `/workspace/classes` using approved dependencies under `/workspace/lib` and create a bounded helper. A registered scenario may supply baseline classes and a reproducer instead. Preserve baseline controls and separate an environment failure from a product failure. Reuse existing successful controls when hashes, inputs and tool versions match; record a reason for a rerun.

Frozen product code, dependencies and supplied baseline classes are immutable. Unchanged-source compilation outputs, scratch scripts and pinned tools stay in `/workspace`. Do not patch or shadow product implementation; tool/classpath substitution must not change product behavior. Ask through `tool_install` or propose an environment change when policy denies a needed tool. Finish with inspected source evidence, cause hypotheses, correction advice, verification steps and uncertainty. A reproduced symptom does not alone prove the causal fault site.

The preset image provides the tool collection in `toolset.txt`. Use the host-supplied readiness inventory for exact installed versions and paths. Target Java remains under `/opt/java/openjdk`; modern JFR/analysis tools use `/opt/esa/tool-jdk` explicitly. Do not substitute the tool JVM for the registered product runtime. For a generic scratch build, pass a complete analysis classpath to Soot (`-cp`) or SootUp (`--classpath`), including `/workspace/classes`, approved dependency JARs and target JDK libraries; the default `/input/classes` classpath applies to registered baselines. Kernel restrictions may limit native sampling or tracing even when a tool is installed.

Soot is preinstalled as `soot` and `/opt/esa/soot/soot.jar`. After a runtime grant, inspect one relevant class with `soot -f jimple -keep-line-number -d /workspace/diagnostics/soot org.example.ClassName`. The launcher uses the separate analysis JVM and the registered `/input/classes`, `/input/deps` and target JDK 8 libraries. Inspect its help with `soot -help`. Keep output in scratch and retain the frozen product classpath for reproductions. Missing classes or phantom references make an analysis incomplete; generated Jimple is static evidence, not a reproduced defect or an independently verified source mapping.

SootUp is also preinstalled. Use `sootup --help` and `sootup --version`. After a runtime grant, prefer a bounded class/method inspection: `sootup jimple org.example.ClassName methodName` or `sootup cfg org.example.ClassName methodName`, redirecting output under `/workspace/diagnostics`. A method filter selects all overloads with that name; use a full method signature for one overload. The default analysis input contains frozen product classes, registered dependencies and target JDK 8 libraries. `--classpath` overrides the entire input classpath; preserve the target libraries when adding scratch classes. CFG text includes statement IDs and normal/exceptional edges. Missing classes, unresolved dependencies and static approximations must be reported as limitations; do not equate graph edges with observed execution or treat statement IDs as source line numbers.

For custom SootUp analyses, the offline bytecode frontend, core/interceptors and callgraph SDK dependencies are in `/opt/esa/sootup/lib/*`. Write auxiliary Java only under `/workspace`, compile with `/opt/esa/tool-jdk/bin/javac --release 17 -cp '/opt/esa/sootup/lib/*' -d /workspace/diagnostics/classes /workspace/diagnostics/Analysis.java`, then run `/opt/esa/tool-jdk/bin/java -Xmx1024m -cp '/workspace/diagnostics/classes:/opt/esa/sootup/lib/*' Analysis`. Classpaths used by the SootUp JavaView are separate from this SDK execution classpath. For call graphs, explicitly mark product inputs as Application and dependencies/target JDK as Library, choose bounded entry methods, and state the CHA/RTA assumptions. Reuse this SDK; do not download or rebuild SootUp per ticket. It must never replace the registered product JVM or classpath.
